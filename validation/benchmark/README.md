# Simulation benchmark

This benchmark measures how well SynTangle removes **presentation tangledness** from extant chromosome structures generated by the forward simulator.

It is deliberately separate from the future ancestral-history benchmark. Hidden fusion/fission/inversion histories are generated and retained, but they are not used to choose an extant layout.

## Benchmark sequence

```text
ancestor
  ↓
logged fusion / fission / inversion
  ↓
extant genomes
  ↓
hidden native presentation
  ↓
whole-chromosome permutation / reversal
  ↓
PUBLIC tangled bundle
  ↓
SynTangle
  ↓
optimized legal layout
  ↓
only then inspect hidden logs/baselines
```

The Python runner imports only the public validation-bundle tables before optimization. Hidden files are read after the solve for descriptive benchmark columns.

## Profiles

### Smoke

Three deterministic, small cases intended for GitHub Actions:

- 3 species / 4 ancestral chromosomes / mild tangle;
- 3 species / 5 ancestral chromosomes / strong tangle;
- 4 species / 5 ancestral chromosomes / random tangle.

Run:

```bash
Rscript validation/benchmark/generate_benchmark_cases.R /tmp/syntangle-benchmark smoke

python validation/benchmark/run_benchmark.py \
  /tmp/syntangle-benchmark \
  --output /tmp/syntangle-benchmark/benchmark_results.tsv \
  --summary-json /tmp/syntangle-benchmark/benchmark_summary.json \
  --summary-md /tmp/syntangle-benchmark/benchmark_summary.md
```

### Full

The full profile spans:

- 3, 4, and 5 species;
- 6, 8, and 10 ancestral chromosomes;
- mild, strong, and random display tangle.

That gives 27 deterministic cases. This profile is intended for Pegasus or another compute node rather than GitHub Actions.

```bash
Rscript validation/benchmark/generate_benchmark_cases.R benchmark_full full

python validation/benchmark/run_benchmark.py \
  benchmark_full \
  --output benchmark_full/benchmark_results.tsv \
  --summary-json benchmark_full/benchmark_summary.json \
  --summary-md benchmark_full/benchmark_summary.md
```

## Recorded quantities

Each case records:

- species/chromosome/anchor scale;
- raw incidence cycle rank;
- chromosome-signature structural cycle rank;
- structural hard-kernel count and largest kernel size;
- hidden evolutionary event count **after** solving;
- number of chromosomes deliberately moved/flipped by tangle induction;
- hidden native-presentation crossing count **after** solving;
- input, normalized, and optimized crossing counts;
- crossings removed;
- lower bound, upper bound, and optimality gap;
- `proven optimum` versus `bounded best known`;
- solver selected;
- states/nodes evaluated;
- wall time.

The hidden native presentation is a useful simulator baseline, not a claim about the uniquely correct biological layout. A different legal layout can have the same or lower crossing objective.

## Scaling interpretation

The benchmark should be read against structural complexity rather than raw anchor count alone. In particular, repeated anchors supporting the same chromosome relationship can greatly inflate the raw incidence cycle rank without increasing chromosome-level rearrangement complexity. The structural-bundle projection is reported alongside the raw graph for exactly this reason.

Large benchmark outputs are working data. Commit scripts and compact summaries, not bulk generated bundles.
